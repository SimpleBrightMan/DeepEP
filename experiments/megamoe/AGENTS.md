# MegaMoE 维护约定

- 以当前已验证的性能分支为基线；整理代码不顺手改变 tile、wave、缓存、credit 或同步顺序。
- 编排层描述角色、wave 和 slice；stage 层绑定地址并执行阶段；CATLASS 层管理物理缓冲和硬件事件。
- 不增加只转发全部参数的包装层。保留函数的理由应是独立职责、真实复用或明确的资源生命周期。
- 专家完整元数据用 `ExpertContext`，当前只读范围用 `ExpertSlice`，下一任务位置用游标；不要重复保存可推导状态。
- AIC/AIV0 计算路径不建立仅 AIV1 消费的 Tensor 视图；配置和分核只派生一次。
- 中文注释解释原因、布局约定、同步依赖和例外；不要逐行翻译，也不写未经验证的性能承诺。
- issued、硬件完成、可见、可复用必须分开。不得以 Scalar 通知替代 FIX 完成；handoff 必须保持唯一资源 owner。
- 被动 timer 不额外排空流水；异步区间保持 ISSUE 语义。计时协议及导出工具必须同步更新。
- 用生产函数的 CPU 行为测试保护推进、分核、所有权和边界，不以匹配函数名替代回归测试。
- 原生验收明确源码/SDK/wheel/JIT 身份，独立输出和缓存。同窗口交替对照、timer-off 测完整通信，报告失败与回退。
- 日常性能筛选遵循`TESTING.md`：优先柜5，提前部署、门禁后连续多BS只跑B一次，已有A明确作历史参考；只有异常或正式验收才补同窗重复对照，不默认ABBA。
- 性能通过不等于精度通过；输出等价回归不等于独立 Golden。未测的 EP、共享专家和兼容路径必须明确列出。
- 不覆盖共享环境、占用其他任务的 NPU、终止其他进程，或将凭据写入源码/日志。
