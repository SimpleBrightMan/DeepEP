# DeepInfer 替换候选：尚未验收

2026-11-17整网适配进展：当前Python/native协议为12；本地整网实验入口位于
`outputs/deepinfer-ours-system-20261117`。新增可选pre-quant路由权重、不同rank本地M与-1掩码、
图计划保留及物理设备映射，默认路径保持原语义。协议12已编译，CPU检查不能替代NPU门槛。
旧协议11仅EP8/M16算子本体获得约15%延迟下降，完整子层额外逐位自洽门槛失败，
没有整网吞吐结论。按当前工作区偏好，本轮整网两边均开启timer。
下面协议10段落是最初兼容性记录，不能作为当前版本/验收状态。

此隔离分支基于个人仓库 main `c5d68f0`，复用 `b1454a2` 的 FP8 共享专家实现，
再显式传递每次调用的 `activation_clamp`。不是已发布 main，也不是可直接部署的版本。
原生接口协议升至 10，必须整体重建，不能与协议 8/9 的旧动态库混装。

`activation_clamp=None` 沿用原不截断行为；正有限 FP32 数值进入原有设备 SwiGLU 的
clampLimit。每次使用独立 tiling 副本，复用 Plan 时不残留上次的 clamp。
CPU 接口测试只证明参数传递和拒绝路径；本分支尚无 CANN 构建及 NPU 精度/性能证据。

还有必须解决的替换障碍：

1. main 在 GMM2 后乘路由权重，DeepInfer 在中间 FP8 量化前乘权重，不能当作数值等价。
2. 当前入口要求各 rank 同一非空 M，不支持 DeepInfer 的 `-1` 无效路由槽。
3. 变路由、固定地址图捕获/回放还需实际设备验证。

下一步先补齐第 1 项的权重传输/应用协议并独立验证，再在同一原始权重、输入、
路由上比较完整 MegaMoE 与完整 MoE 子层。不能关闭共享专家、取消 clamp、把无效槽
变成真实路由，或只取 rank-min 来制造替换收益。正式样本 timer-off；诊断另取。

本分支仍使用 main 的权重预排和 Wave 调度。DS 准备后的权重不能直接交给本分支；
应从同一份原始 FP4 位模式和原始 E8M0 scale 分别准备，转换不计入稳态测量。
