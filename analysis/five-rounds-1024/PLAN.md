# R31合并版：五轮因果实验

冻结生产基线：`904131c`（分支文档tip `9f35634`），设备库SHA256 `9c8f7a913d0b61584acda6900db24698f5d9af40a3033797415c402631c7cacb`。不能称为全EP最优：已知EP8大BS约2%收益，EP32/128当前版本缺完整成绩。

共同合同：EP8/32，先筛BS512/1024/4096；H7168/I3072/E384/topk6/共享0，FP8/FP4，balanced seed20260922。每项只改变一个机制，与当前冻结基线同窗口ABBA，完整通信kernel、timer-off、warm10/采20取后10；同时记录rank-max和输入/输出指纹。跳过独立Golden，不能称精度验收通过。保留独立被动流水及配对CSV。

| 轮次 | 最小改动 | 假设及反证 |
|---|---|---|
| R1 | Combine每次最多服务本owner 1行，再回调度器 | EP8 CV每owner通常2–4行，8行配额不会生效。1行可让激活/Dispatch更早推进，但可能增加Scalar和元数据开销。 |
| R2 | 先提交一个可用激活，再接收GMM2完成事件 | 新增的真实FIX等待可能挡住本可并发的VF/MTE3；只换次序，不删等待或改变ready所有权。小任务CV路径不改。 |
| R3 | 中大BS配对wave按一轮AIC预算 | 进一步缩小尾部，代价是更多wave/完成事件。GMM2最低一轮约束不变，小BS原预算不改。 |
| R4 | 中大BS配对wave按三轮AIC预算 | 与R3形成双向对照，检验异步完成后更大wave是否能摊薄边界；可能放大末两波Combine。 |
| R5 | 用前四轮中真实有效项做组合验收；如均无效，改测Combine 4行配额 | 组合收益必须重测，不相加；1行无效时检验温和切片能否避开调度开销。最终保持一份统一源码，不按shape挑分支最低值。 |

每轮记录：精确分支/提交、编译与原生身份、实际启用路径、性能/范围、输出回归、流水落点、是否保留及下一轮判断。失败/资源阻塞保留原记录，不计作完成的优化实验。

资源：只在空闲设备启动；排除已有NPU上下文和准备入卡的外部作业，不终止其他任务。多轮扫描01/05/06/07，必要时使用已有授权跳转。EP128需16节点同时空闲、软件与拓扑一致；机会窗口优先测冻结当前分支，不用EP8候选冒充当前版。

## 执行调整与首轮反思

- EP8先完成三BS完整ABBA。EP32多次四节点窗口被外部训练打断，改为先锁定历史大M回退最关键的BS4096，对五项各做独立对照；有收益项再扩BS512/1024，未测不填数。
- R1的EP8三BS分别+0.25%/−0.19%/−0.14%，输出逐rank哈希一致；BS512控制两次差4.82us，不能视为稳定收益。R2的大BS仅+0.004%，R3/R4的大BS回退。故R5不叠加未证实有效项，按原计划测4行配额。
- R2没有修改EP8 BS512/1024启用的CV任务路径，这两项微小波动不能归因于其完成接收顺序。R3/R4的设备SO与基线逐字节相同，只有实际host wave预算改变。
- R3在01CPU6一次SHMEM初始化失败，原生日志明确为端口占用（尚未进入kernel）。后续启动端口必须避开内核临时端口范围，并在全组READY前检查连接占用，不修改系统端口设置。
- 所有失败和不完整对照独立保存；后续换节点是新条件，不能与此前单次基线混算。
