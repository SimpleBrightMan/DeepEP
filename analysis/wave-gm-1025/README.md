# 统一 Wave+GM 对照

父版本为推荐统一Wave基线`4a0de857`，不包含提前归约或扩大rail的实验。分支`codex/megamoe-wave-gm-1025`。

- 单一修改：`UseGmm1CvForLaunch`统一返回false，host预算、device UB绑定及kernel派发共同切换至既有GM路径。不改数学计算、gate/up配对、两轮Wave、BS≥512的lag或原Dispatch/Combine通知。
- 基线原本仅EP8且期望每专家M≤128时使用CV：本模型EP8 BS32/96/256/512/1024变更，BS2048/4096不变；EP32七个BS原本就全部GM，是算法层负对照。统一常量可能消除运行时判断、改变生成代码，因此不是二进制相同的对照；不能直接把其变化归因于GM中转。
- GM路径不等于只增加一次GM往返：它同时采用既有GM完成/消费粒度、64行激活量子和6个Dispatch/2个Combine UB槽；CV路径是原生32行量子和2/4槽。实验检验现成GM后端的组合，不声称隔离单次GM流量。
- 默认计时器仍是完整被动版：主性能timer-off；另采rank0全部32组AIC/AIV0/AIV1流水，成对保存CSV，不为timer增加同步。
- EP8/EP32各七BS，同节点有序列表、连续多BS、同窗ABBA。核对原生身份及输出差分，不跑独立Golden；未完成结果不补造。
- 上一轮连续TCPStore测试有主机协调故障。本轮只在隔离测试控制层使用CPU Gloo（预检先确认可用），设备Dispatch/Combine仍为SHMEM/MTE，不引入HCCL或将CPU通信计入kernel。两方案使用相同控制层，记录该差异，不与旧窗口绝对时间混算。

## 实测结论（2026-10-25）

原生候选`095b4c7f`已在B080完成host/device构建；计时外CPU Gloo测试控制层不属于原生优化。

两套完整连续七BS ABBA，各两次独立启动；capacity4096、完整通信、timer-off，20次取后10次逐轮rank-min均值，另保存rank-max；不能把rank-min称为最慢卡延迟。

EP8各项均在±0.5%，整体基本持平，不宣称完全无损。EP32原版已经是GM，BS1024约慢1.48%；单点确认仅完成AB（1420.08→1456.26μs，慢2.55%），第三次启动在CPU Gloo prepare出现24/4字节collective不匹配，未进入计时kernel，根因未定，后续停止。确认试验不算完整ABBA，也不替换正式矩阵。暂不替换推荐基线，不外推EP64/128。

全部8/32rank输出有限且版本/重复/timer-on-off指纹一致，未跑独立Golden。完整矩阵加单点有效A轮共1808份CSV、30份完整rank0被动流水，本地归档；没有为打点新增同步。完整矩阵最大正向打点开销约1.55%，含额外单点复核最大2.57%；负差值视为测量波动。
