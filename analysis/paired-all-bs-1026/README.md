# A8W4：取消 BS4096 的配对与 Wave 策略分界

基线：新 main `7de059fc5b5534c660926c51b84b7e3687b89915`。
候选分支：`codex/megamoe-paired-all-bs-1026`。本次不直接更新 main。

## 修改边界

| BS/卡 | 旧 main | 本分支 |
|---|---|---|
| 1～256 | 配对、原小BS Wave预算、lag关闭 | 不变 |
| 257～511 | 配对、两轮AIC预算、lag关闭 | 不变 |
| 512～4096 | 配对、两轮AIC预算、lag开启 | 不变 |
| 4097～65536 | 非配对、非配对Wave预算、lag开启 | 配对、两轮AIC预算、lag仍开启 |

- kernel派发删除A8W4的非配对选择；A8W8不变。
- host中BS>256的A8W4统一使用原BS4096的Wave预算。
- 兼容导出`paired_gate_up_max_tokens`从4096改为65536，使Python及local-compute现有选权重逻辑覆盖全部合法BS。
- 保留legacy planar prepared副本和不可变检查，不顺手删除准备流程或改变返回对象。
- 实际BS、输入/输出容量、路由、Dispatch/Combine、UB/L1、供数计划、缓存、完成事件、数学规则和timer实现均不修改。不把大BS截断或伪装成4096。
- 65536仍是接口输入上限，不代表所有模型/容量组合都能发射；原GM/SHMEM/UB容量检查继续生效。

## 性能判断

在H7168/I3072、32个AIC下，BS>4096的M-group预算由6改为3。相同M-group数量时Wave通常更多、每波更小；可能减小下游启动/尾部等待，也可能增加handoff和Wave边界成本。

BS≤4096的算法选择与预算保持不变，但本次未比较原生机器码，也没有NPU复测，不能承诺编译产物或性能完全不变。BS>4096更不能称为无损重构，需单独做真实输出回归和同窗完整通信性能对照。

需要重新构建安装Python/native配套包；不能混用旧版导出4096的扩展与新版派发库。

- 公共API：4096、4097、8192均选择配对权重，计划BS保持真实值，调用热路径不增加format cast。
- 编译执行生产host预算片段：覆盖256/257/4096/4097/8192/16384/65536及尾Wave，A8W8预算不变。
- 编译执行生产kernel派发片段：EP8/32/64/128、BS1～65536的边界样本均选择A8W4 paired GM，A8W8仍选择原入口。仅将设备launch语法替换为模板身份记录函数，不模拟计算。
- 原供数、常驻UB容量和packed权重映射测试通过。

测试使用任务目录内的pytest与Zig C++工具链，不安装到共享服务器环境。未进行CANN原生编译、NPU执行、独立Golden、性能测量；没有新增性能结果。

建议下一步：先在独占设备上比较BS4096与8192，核对实际加载的包/库身份、输出、完整通信Duration及Wave数，再决定是否合入main；大BS需先核对内存容量，不直接运行65536压力用例。
